# M4: Quality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whole-utterance final decoding, an optional final-stage model, dictionary commands with live reload, partial text in the panel (globally or per app), the remaining M2/M4 follow-ups, and measured defaults under CPU load.

**Architecture:** Changes stay inside the existing units: `koeinput-core` session/engine/config/postprocess, the daemon's loader and service, the CLI, and the addon's glue and config. The only D-Bus change is two added read-only properties (backward compatible). Two streams run in parallel: Rust (Tasks 1–3, 5, 6 in order) and the addon (Task 4).

**Tech Stack:** Rust 1.95 workspace (sherpa-onnx 1.13.8 no-TTS), zbus 6; C++20 fcitx5 addon (5.0 and 5.1); podman build images.

**Spec:** `docs/superpowers/specs/2026-10-18-m4-quality-design.md` (read it first). Open findings: `docs/followups.md`.

## Global Constraints

- Never copy code from fcitx5-vinput (GPL-3.0).
- Builds and tests only through `scripts/dev` / `scripts/addon` (both images for the addon), never against the user's session bus; heavy commands under `nice -n 10`.
- The user's recordings in `work/eval-data/` are never quoted, copied into the repository, logged, or put into tests; only aggregate numbers go into docs.
- Recognized text is never logged unless `KOEINPUT_LOG_TEXT=1`.
- Config defaults: `final_full_max_ms = 30000` (range 0–120000, 0 = off), `final_model = ""`.
- Addon setting "Partial text": `InApp` (default), `Panel`, `Off`; "Apps that show partial text in the panel": list of program names, default empty, case-insensitive match on `InputContext::program()`. Old boolean `ShowPartial=False` maps to `Off`.
- Dictionary file `~/.config/koeinput/dictionary.tsv` (`wrong<TAB>right`), written through a temporary file and rename, comments and order kept.
- Comments only for non-obvious context; no bare task numbers in comments.
- Commit messages in English, ending with `Co-Authored-By: <the model that wrote the commit> <noreply@anthropic.com>`.
- Every shell command starts with `cd <worktree> && `. No background processes left running, no commands that wait on stdin. Never run `koeinput listen` or the microphone test.

## Review Focus

1. A long dictation (over 30 s of speech) → the final text still arrives (segment join fallback) and nothing is lost. Test: Task 1 `long_utterance_falls_back_to_segment_join`.
2. The final-stage model is missing or fails to load → dictation keeps working with the main model, and `status` says why. Test: Task 2 `final_model_load_failure_keeps_main_model`.
3. The dictionary file is edited while a session runs → the running session is unaffected, the next session uses the new entries, a broken line is skipped with a warning. Test: Task 3 `dictionary_reload_between_sessions`.
4. An app on the per-app list → partial text never reaches the app's preedit, so nothing can be committed on blur. Test: Task 4 per-app scenario.
5. Measuring under load does not leave load processes running. Test: Task 6 script cleans up (trap).

### Task 1: Whole-utterance final decode

**Files:** `crates/core/src/session.rs`, `crates/core/src/config.rs`, `crates/core/src/engine.rs` (only if the session needs more audio kept), tests in those files.

- [ ] Tests first in `session.rs` (fake recognizer that records the spans it was asked to decode):
  - `final_decodes_whole_utterance`: two speech segments with a pause, stop → exactly one final decode call whose span starts at the first segment's start and ends at the end of the recording; the final text is that decode's text (post-processed); partials before the stop still come from per-segment decodes.
  - `long_utterance_falls_back_to_segment_join`: span longer than `final_full_max_ms` → today's join of segment texts.
  - `final_full_disabled_with_zero`: `final_full_max_ms = 0` → today's behavior.
  - `whole_utterance_decode_error_reports_model_error`: the final decode fails → `Error` code `model`, state `error`, no `Final`.
  - `no_speech_still_gives_empty_final`: no segment → empty final, no decode call.
- [ ] Config: `final_full_max_ms: u64` with default 30000, validated 0..=120000 (same style as the other timing fields), and `SessionConfig` carries it in samples.
- [ ] Implement in `Session::finalize`: keep the audio from the first speech start (the session already keeps the audio; check memory: 30 s at 16 kHz f32 is 1.9 MB, fine), decode the span once when within the limit, else join as today.
- [ ] `scripts/dev cargo test --workspace`, the D-Bus tests, clippy, fmt. Commit "Decode the whole utterance for the final text".

### Task 2: Optional final-stage model

**Files:** `crates/core/src/{config.rs,engine.rs,build.rs,session.rs}`, `crates/daemon/src/{main.rs,service.rs}`, `crates/cli/src/{main.rs,model_cmd.rs,listen.rs}` (status), tests (`crates/daemon/tests/dbus.rs`, `crates/cli/tests/cli.rs`).

- [ ] Config key `final_model: Option<String>` (empty string = none); `set_final_model(path, Option<&str>)` like `set_model`.
- [ ] `Engine` gets `final_rec: Option<Arc<dyn Recognizer>>`; the session uses it for the whole-utterance final decode (and for the fallback's segment decodes at the end), the main recognizer for partials.
- [ ] `build.rs` (`load_engine`) loads the final-stage model when configured and installed; a load failure is logged and recorded (the engine works without it).
- [ ] Daemon: `Ready` is true when the main model is ready. Two read-only properties are added to `org.nemui.KoeInput.Recognizer1` (a backward-compatible addition): `FinalModel` (s: the configured final-stage model id, empty when none) and `FinalModelReady` (b). The load error goes to the journal. `koeinput status` prints `final model: <id> (ready|not loaded, see journalctl --user -u koeinput)` or nothing when none. Update `crates/dbus-api` (proxy) accordingly.
- [ ] CLI: `koeinput model use ID --final`, `koeinput model use --final none` (clap: `id` optional only with `--final`), `model list` marks the final-stage model.
- [ ] Tests: session test that the final uses the final recognizer and partials the main one; daemon test with a fake final recognizer (`KOEINPUT_TEST_FAKE` + a new `KOEINPUT_TEST_FINAL_FAKE=1` hook that returns `F<seconds>`): `Final` text comes from it; `final_model_load_failure_keeps_main_model` (`KOEINPUT_TEST_FINAL_LOAD_FAIL=1`): sessions still work with the main fake. CLI test for `model use --final` writing the config.
- [ ] Suites, clippy, fmt. Commit "Add an optional final-stage model".

### Task 3: Dictionary commands and live reload

**Files:** `crates/core/src/postprocess.rs`, `crates/core/src/engine.rs` (reloadable post-processor), `crates/daemon/src/service.rs` (reload at session start), `crates/cli/src/{main.rs, new dict_cmd.rs}`, tests.

- [ ] `koeinput dict add WRONG RIGHT` / `dict remove WRONG` / `dict list`: edit the TSV through temp + rename (resolve symlinks as `set_model` does), keep comments, blank lines and order; `add` replaces an existing entry for the same wrong form in place; refuse empty forms and forms with tabs or newlines.
- [ ] Reload: the engine holds the dictionary path and the `(mtime, len)` it loaded; at each session start, one `std::fs::metadata` call; when it changed, reload (warnings for bad lines as at startup); a missing file means an empty dictionary. The running session keeps the post-processor it started with.
- [ ] Tests: CLI tests (`dict add` twice replaces, comments kept, `remove` of a missing entry reports it, `list` output); `dictionary_reload_between_sessions` (daemon or engine level with the fake recognizer returning a fixed word that the dictionary then replaces).
- [ ] Suites, clippy, fmt. Commit "Add dictionary commands and reload the dictionary per session".
