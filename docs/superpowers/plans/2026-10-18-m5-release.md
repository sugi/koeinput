# M5: More Formats, CI and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ubuntu, Fedora and Arch packages next to the Debian ones, user documentation, a private GitHub repository with CI, and documented release steps.

**Architecture:** Every format builds from the same three orig tarballs made by `scripts/make-orig` (main tree, filtered vendor tree, pinned no-TTS sherpa-onnx archive), offline, in a podman image per distribution, followed by an install test in a fresh container. GitHub Actions calls the same scripts.

**Tech Stack:** podman, dpkg-buildpackage (Debian/Ubuntu), rpmbuild + rpmlint (Fedora), makepkg + namcap (Arch), GitHub Actions on `ubuntu-24.04` runners.

**Spec:** `docs/superpowers/specs/2026-10-18-m5-release-design.md` (read it first). M3's packaging is the model to follow: `debian/`, `scripts/{make-orig,build-deb,test-deb,gen-copyright,check-no-gpl,sherpa-onnx}`, `packaging/`.

## Global Constraints

- No GPL code in any binary: every build uses the pinned no-TTS archive (`packaging/sherpa-onnx.env`) with the stub archives, and runs `scripts/check-no-gpl` on the unstripped binaries before stripping.
- Builds offline (`--network=none`) from the orig tarballs; images may use the network when they are built.
- Package names `koeinput` and `fcitx5-koeinput`; installed paths as in M3 (with each distribution's library directory for the addon).
- Version 0.1.0; Debian/Ubuntu revision `-1` (Ubuntu builds get a local `~<dist>1` suffix at build time, not committed); RPM `Release: 1%{?dist}`; Arch `pkgrel=1`.
- The user unit is never enabled at install; the daemon starts by D-Bus activation.
- Heavy commands under `nice -n 10`; podman `--init` does not work on this machine (no catatonit) — use the PID-1 approach of `scripts/test-deb`.
- Docs in plain English (README.ja.md in plain Japanese); never quote recognized text or the user's recordings.
- Comments only for non-obvious context; no bare task numbers.
- Commit messages in English, ending with `Co-Authored-By: <the model that wrote the commit> <noreply@anthropic.com>`.
- Every shell command starts with `cd <worktree> && `. No background processes left running; no commands that wait on stdin. Never run `koeinput listen`, the microphone test, or anything against the user's session bus.

## Review Focus

1. A distribution's packages install but the addon is not loaded by that distribution's fcitx5 (different addon directory) → the install test proves the headless fcitx5 load per distribution.
2. A Fedora/Arch build accidentally downloads (network) or uses the TTS archive → offline build plus the GPL check fail it.
3. The Ubuntu 24.04 build picks the old rustc 1.75 → the build fails fast with a clear message, or the PATH change selects 1.91; the test proves the produced binary runs.
4. README install steps that do not match the built package file names → a check in the docs task lists `target/` outputs and compares.
5. CI that passes without running the real checks (skipped jobs, missing `set -e`) → the controller reads the run logs on GitHub.
